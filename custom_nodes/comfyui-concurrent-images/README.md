# 分块并发提交 / 分块并发取回

两个 ComfyUI V3 自定义节点，分类 `API易/并发`。备用生成直接执行本机官方 `OpenAIGPTImageNodeV2`，使用 ComfyUI 账户积分；不修改官方节点或核心文件。也可选「仅官方节点」。

## 使用

1. 安装目录 `custom_nodes/comfyui-concurrent-images`，重新启动 ComfyUI、刷新网页。依赖复用本机 requests、Pillow、numpy、torch 和官方 API 节点，不需安装其他运行库。
2. 加载附带的 `API-并发-官方备用.json`，填写提示词。它接好：自动分块 → 并发提交 → 按序取回 → 原 ImageUntile+ → 裁回原尺寸 → 保存。
3. 并发数自动等于待处理分块总数；两块就同时发两次，参考图不增加并发数。每块请求固定 `n=1`，请求尺寸取原分块宽高。API易超时固定900秒，不提供设置框。
4. `API易→官方备用`：直接调用本地 `comfyui-apiyi-gpt` 的设置读取函数，复用 `config.json` 的模型列表、默认模型、返回格式及 `APIYI_BASE_URL` 地址覆盖；密钥沿用 `APIYI_API_KEY`。API易模型改为下拉选择，面板不再有地址或底部空白状态框。失败先按设定次数退避重试，然后只把失败块切换官方。认证/参数等明确拒绝直接切换备用。官方沿用当前登录信息，或 `COMFY_API_KEY` 环境变量。
5. 同图、同参数、同任务种子复用同一个任务；换任务种子新建整批。种子只标识本地任务，官方并不承诺种子复现。

## 逐块参考图

- 提交节点增加可扩展的「参考图_1、参考图_2……」输入口，每路接入一组参考图分块批次或IMAGE列表；不接也可生成。
- **每路参考图的总张数必须与待处理分块总张数相等**。目标第1块只读取各路参考列表第1张，第2块读取第2张。数量不符在提交任何生成前报错；不随机、不广播、不循环补图。
- 每次API请求中的图1是当前待处理分块，图2是「参考图_1」的同编号图，图3是「参考图_2」的同编号图，依次类推。参考输入口按数字排序，输入口内按列表/批次原序展开。
- 参考图连同编号、顺序、SHA256一起持久化；失败重试、切换官方备用及断点恢复都使用同一编号参考图。改动参考图会创建不同任务，避免错用旧结果。
- 旧工作流升级会保留原来的提示词、模型、重试次数和任务种子，移除已取消的设置口。也可直接重新导入更新后的工作流。

## 断线与重试

- 独立后台进程执行任务。关闭网页、取消 ComfyUI 的等待或重启 ComfyUI 不会主动终止已经提交的后台生成。结果立即写入 `output/ConcurrentImages/<任务编号>/`。不要删除仍在工作的任务目录。
- 重新运行原提交节点（输入、参数、种子相同），或者把原任务编号填到取回节点，可恢复同一批。取回等待中每10秒检查后台，异常退出则重启；已完成块不会再次提交。
- 已保存的 API 响应下载失败，只重试下载。官方响应通过当前版本原生请求日志镜像保存，恢复时复用官方解码/下载函数；日志格式兼容性已用本机版本模拟验证，未来官方版本改变后须复验。
- 结果内容损坏或下载链接明确过期（404/410）时，按剩余生成重试额度重发，耗尽则切换备用。普通网络下载失败保留响应继续下载，不重新生成。
- 如果 API易的**生成连接本身**断了，或者进程在拿到完整响应前被强制结束，原结果无法查询；按用户要求自动重新生成，可能重复计费。此限制不能靠本地任务编号消除。官方节点自身也有网络重试；本节点的“每接口重试次数”是外层重试上限，不等于总HTTP尝试次数。
- 重试耗尽后保留失败编号并停止拼接。重新登录/修复接口后，取回节点开启「重试失败块」再运行，只重试失败块；每次明确运行会给这些块新一轮额度。平常保持关闭。
- 本机重启、后台进程死亡后，需要重新运行取回节点；没有注册开机服务。凭原编号续取成功结果，无需再次提供输入图片。官方未完成请求恢复时需要有效登录。

## 顺序、尺寸和限制

- 输入 IMAGE 列表按列表顺序展开，列表中的批次按张量顺序展开。每块绑定不可变编号、输入SHA256、独立尝试记录、输出SHA256。返回速度不改变编号。
- 全部成功后按 0、1、2… 输出单个 IMAGE 批次；不跳过失败、不用原图占位。数量、编号、输出校验和不符合时停止。不要手工改任务记录。
- 默认严格检查原块尺寸；接口改尺寸时停止。可明确选择「缩放回原块尺寸」，使用 Lanczos，只改变输出尺寸，不会重新调用生成。RGBA 结果保留 alpha，混合 RGB/RGBA 时只给 RGB 添加不透明 alpha。
- 工作流一次处理一张原图的分块；多张原图请分别提交，否则原分块器的多图排列不能直接用一次 ImageUntile+ 还原。
- 输入/输出编码为8位 PNG；不适用于保留 RAW、16位或ICC的生产链。官方节点会沿用其自带的参考图缩放与尺寸约束（16倍数、最长边3840等）。
- 并发数针对单批；不同批次分别有工作进程。任务目录保留输入、结果和响应，长期使用需自行归档清理。密钥只通过进程环境在内存中传递，不写进工作流和任务清单。

## 验证范围

19项引擎测试、10项节点检查、旧工作流参数迁移测试：模拟 HTTPS 服务验证真实独立进程的并发、乱序、强制终止后续取与不重发成功块；覆盖参考图同编号配对、篡改拦截、主备及重试保持配对、两类接口的传图顺序。本机官方节点执行与原生响应日志恢复已用模拟响应验证；安装版分块器和 ImageUntile+ 四块回环已通过。

未运行付费真实生图，未验收AI照片跨块接缝或色彩一致性。并发保证调度与排列，不保证模型在相邻分块中生成一致内容。
